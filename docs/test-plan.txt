Conformance and hardening test plan
===================================
Run: python3 -m unittest discover -s tests -q
Catalog: python3 -m hearthstone.catalog
Hashes: python3 -m hearthstone.manifest
Current measured results are in CHANGELOG.txt, rather than per-stage reports.

1. Catalog structure and semantics
   Validate the schema itself and all current definitions. Reject malformed
   stats, kinds, keywords, targeting, policies, effects and exact references.
   Negative tests assert the expected diagnostic, never merely any error.
   Verify the current manifest; Git history preserves previous definitions.

2. Representative-card behavior
   tests/test_conformance.py, test_drawing.py, test_combat.py, test_deaths.py,
   test_stats.py, test_match.py, test_keywords.py, test_zones.py, test_reactions.py.
   See mechanics-coverage.txt and card-inventory.txt for the card mapping.
   test_hardening.py adds live Kobold Spell Damage, source removal, unaffected
   hero powers/fatigue/Battlecry, operation dispatch, and private player views.
   Counterspell/Lightning Bolt regression expects spent mana, no damage and no
   pending Overload, following the archived Blizzard explanation.

3. Public legality and random-game properties
   test_actions.py exercises every listed action from each state in six seeded
   random games, rejects sampled invalid targets/positions/sources atomically,
   and checks every mulligan subset, capacities, Secrets and power usage.
   Drive games exclusively through legal_actions/apply, excluding concession
   from random choice so games reach natural or turn-limit results.
   After each action: board <= 7; hand <= 10; positive minion Health in PLAY;
   unique entity/deck IDs; matching deck membership; nonnegative mana; no pending
   reactions. Finished games offer no actions and reject result-changing actions.
   Periodically restore through JSON, then compare repeated complete traces.
   Larger reproducible run:
     HS_RANDOM_GAMES=100 python3 -m unittest discover -s tests -p test_actions.py -q

4. Privacy, replay and copy isolation
   Swap opponent private card/Secret identities and IDs, reorder either deck,
   and change RNG state: the player view must stay identical. No hidden identity
   or handle may occur in projected entities/events; DRAW is redacted, BURN and
   REVEAL remain public. Public bounces retain known hand cards. Mutation of a
   detached view does not affect the game. Current generation is deterministic;
   private random choices use explicit controller-only events and offer projections.
   test_events.py checks frozen nested payloads, shallow sharing, independent
   branch sequences, JSON restore and failed-action rollback.

5. Measured performance and code style
   python3 tools/bench.py --games 100 --seed 0
   Measures enumeration + execution (excluding engine/deck setup and hashing),
   using a separate seeded driver RNG. For an alternating before/after comparison,
   pass --event-copy deep (former copying) or --event-copy shared (current). Report actions/s and a SHA-256 digest of
   full final states, traces and events. Compare equal workloads before/after.
   python3 -m pip install -r requirements-dev.txt
   python3 -m black --check hearthstone tests tools examples
   Formatting was checked with equal ASTs and before/after passing suites.

Limit: these tests validate the stated historical fixture policies, not complete
Hearthstone or live-patch parity. Client logs and broader card coverage remain.

Stage 10 additions
------------------
test_random_choices.py covers 36 schema, random, choice, privacy, scheduling and
complete-game scenarios. Exercise Arcane Missiles (including extra Spell Damage
hits), Mad Bomber self-exclusion, Deadly Shot eligibility, Book private generation,
Stonehill offers, and both Wrath branches. Check empty/small pools, seed variation,
canonical pool order, full hands, countered spells and bounded resolution.
Paused commands preserve committed board/resource/RNG/event invariants; verify
JSON branching, nested and off-turn choices, Deathrattle and turn-start resumption,
wrong/stale answers, private generated Secrets, and non-interference of hidden
offer/continuation changes. The complete seed-8 demo replays every action through
JSON checkpoints and includes both Discover and Choose One. The random-game
driver selects the pending chooser rather than assuming the active player.
CI also runs on stacked pull requests whose base is another feature branch.
