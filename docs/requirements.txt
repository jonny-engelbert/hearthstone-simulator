Current card definition and execution contract
=============================================
Updated 2026-10-21: schema 1.12; catalog foundation-v12; 60 definitions.
Card-data profile: wild-11.0.0.24118-subset; rules parity remains unverified.

Data and versioning
-------------------
FND-01: Definitions use exact (cardId, revision) references; instances have unique
IDs and owner/controller/zone state. Display text is never executable logic.
FND-02: One current catalog, card schema, integration schema and hash manifest,
updated in place. Git
preserves releases. Old revision labels identify definitions, not rule branches.
FND-03: Reject unknown fields, operations, versions, incompatible kinds and
unresolved references. Validate structure before semantic constraints. Diagnostics
identify the relevant discriminated schema branch and offending field/rule.
FND-04: Minions require Attack/Health, weapons Attack/durability, spells/powers
mana cost only. Keywords, mechanics and ability kinds must agree.

Execution and combat
--------------------
Targeting: REQUIRED prohibits play without a legal selection;
REQUIRED_IF_AVAILABLE requires a selection when available; OPTIONAL permits none.
Selectors and selected-target legality are separate (area damage ignores Stealth
and Elusive). Board/hand/deck caps: 7/10/99. Mana is never negative.
Damage: capture a batch's recipients and Spell Damage once; resolve every hit
before its death checkpoint. Shield, Immune and Armor use the common pipeline.
Spell Damage: sum SPELL_DAMAGE amounts on living, non-pending, non-silenced
friendly minions in PLAY. Ignore sources in other zones, and enemy sources.
Only SPELL-class damage receives this bonus, not hero powers, abilities or fatigue.
Healing: cap at damage taken. Buffs are additive. Auras are flat friendly-minion
modifiers. Health loss uses CAP_CURRENT_ON_MAX_LOSS. Silence removes operative
keywords, buffs, Freeze and abilities. Transform resets the instance definition.
Combat: validate readiness, Attack, attack counts, Freeze, Rush/Charge and Taunt;
normal hits/retaliation capture Attack before applying damage. Weapons equip,
replace, spend durability and run destruction scripts through the same scheduler.
Entry stamps are explicit, unique and monotonic; there is no unstamped fallback.

Draws, zones and death resolution
--------------------------------
Draw explicit deck order. A full-hand draw publicly reveals/burns the card.
Empty decks escalate fatigue, even with a full hand. Summons do not run Battlecries.
Generated instances get fresh IDs. Bounce/shuffle reset board modifiers; Gang Up
creates clean base-definition copies. Death snapshots preserve last-known state.
DEATH_WAVES_FIFO: remove each ordered death batch, then resolve its snapshots
before collecting the next wave. Flat aura refreshes and nested deaths settle
before returning control. Reaction/Deathrattle budgets fail atomically.

Managed matches and reaction timing
----------------------------------
Seeded setup/mulligan, Coin, complete turns, mana growth/refill, temporary mana,
Overload locks, power usage, readiness, expiration and Freeze thawing belong to
MatchEngine. Fixture primitives are not legal public player actions.
Counterspell spends mana/card and still counts a play, but suppresses spell text,
Overload and AFTER_SPELL. The hardening review's proposed Overload reversal is
contradicted by Blizzard's archived answer (see reactions-stage9.txt).
Reactions snapshot eligible sources, run depth first with explicit bounded work,
revalidate sources and complete before the next decision. Attack interruptions
can cancel or redirect; a returned state has no pending reaction frames.

Public APIs and privacy
-----------------------
apply accepts mulligan/play/hero_power/attack/end_turn/concede/choose dictionaries.
legal_actions reuses execution validators; returns canonical concrete actions.
Enumerate all mulligan subsets (at most 16), each legal target and each minion
position. Omitted target means none; minion positions are explicit. Equivalent
optional-null/default spellings accepted by apply are not duplicated in the list.
Finished games return []; inactive/waiting players can only concede, except
that a pending choice belongs to its explicitly named player, even off-turn.
view returns own hand, public entities, counts, public resources and filtered
events. Deck instances/order are hidden for both; opponent hand/Secrets have no
private handles. Public bounce/reveal/exact public generation can identify hand cards;
drawing/shuffling clears that knowledge. No RNG, scheduler, stamps, provenance
pointers, death snapshots, mulligan choices or setup deck lists cross this API.
Full states, raw event logs and checkpoints remain private debug data. Views are
not restorable checkpoints. Random/Discovered cards use CONTROLLER_ONLY events
and privateTo instance visibility, including full-hand generation discards.
Playing a normal card makes it public; Secrets stay hidden until countered or
revealed. Private generation events stay redacted even after later public play.

State copies and development policy
----------------------------------
Actions return independent mutable game state. Historical event payloads are
immutable and shared safely; each state owns its log sequence. JSON export/
restore stays plain and deterministic. Payload list copies are shallow O(n),
not deep copies of all prior events; a fully persistent log is not implemented.
No new per-stage snapshot/doc/report files: update current files and CHANGELOG.
Historical stage notes retain detailed fixture policies; code/tests are current.
Future: a single pinned client/card profile with client-log conformance evidence.

Seeded randomness and decision transactions (stage 10)
-----------------------------------------------------
Random recipients are uniform over live eligible characters in selector/entity
order. They use effect eligibility, not selected-target restrictions. Empty sets
consume no RNG. RANDOM_DAMAGE reselects after each hit and its reactions/deaths;
Spell Damage adds hits, not damage per hit. Results retain the existing atomic
card-result checkpoint. Countered effects consume no random draws.
Card pools are explicit filters over current collectible catalog definitions,
sorted by (cardId, revision), not the full Hearthstone collection. ADD_RANDOM_CARD
samples once; DISCOVER offers up to three distinct definitions without replacement.
The Stonehill fixture uses only Neutral Taunt minions, uniformly, without historical
class weighting. New card stats follow the pinned extracted data (Book 1/1, Stonehill
1/4); all card values follow build 24118; not all rules have verified client parity.
CHOOSE_ONE offers labeled effect branches; these share the ability's preselected
target (Wrath). Branch-specific targeting and full-format Discover pools are future
content/API extensions, not silently inferred from text.
A pending CHOICE retains the committed execution root and stores a detached
provisional prefix beside the continuation. Views show the prefix at the prompt:
Discover shows spent costs, the played card and all preceding effects/events.
Root Choose One shows the pre-play hand/mana to its chooser and leaves the
opponent's entire view unchanged. Nested/off-turn choices show their actual prefix.
Only the chooser sees options; no runtime frames enter views/checkpoints. Replay
with saved hashed answers commits the final action once, with unchanged final
bytes under the same catalog. Conceding ends at the visible prefix. See
review-and-decisions.txt for sources, timing policies and known limitations.
choose(state, player, choice_id, option_id) and apply's choose dictionary resume.
Only that chooser may choose; both players can concede, ending at the visible prefix and discarding remaining effects.
Other actions are blocked. Views show offers only to the chooser, without effect
scripts or continuation data. No unchosen private offer is published in events.
Defaults: 32 choices per action, 1000 random selections, eight effect nesting
levels. Budget failures and invalid/stale choices preserve the input state. No
Python generators, stack frames, engine globals or external state are serialized.

Constructed decks and integration contracts (stage 11)
------------------------------------------------------
DECK-01: new_constructed_game selects FOUNDATION_CONSTRUCTED_V1. Its pool is
exactly the current catalog's collectible MINION/SPELL/WEAPON definitions, pinned
by the canonical catalog SHA-256 returned by contract() (definitions sorted
by cardId/revision, so source-array ordering is immaterial). Supported heroes are
MAGE/Fireblast, PRIEST/Lesser Heal and PALADIN/Reinforce. Other heroes lack their
implemented powers and are rejected. A deck has exactly 30 cards, Neutral or
matching hero class, at most two of each cardId, one if any catalog revision of
that identity is Legendary. Copy identity spans revisions; alternate-print
aliases are not present and require an explicit format extension. Strings resolve
only an unambiguous definition; exact references normalize to cardId/revision.
Reject unknown formats/classes/references, noncollectibles, tokens, powers, wrong
classes and copy violations before setup. Input decks are never mutated. Mana
cap is ten and powers follow the chosen classes; arbitrary overrides are absent.
DECK-02: This is a supported historical foundation format, not current Standard,
Wild, Arena, collection ownership or a complete live-client deck validator.
Starting-deck restrictions are not re-applied after generation, transformation,
or shuffle effects. new_game remains the explicitly marked FOUNDATION_SANDBOX
fixture API with configurable deck sizes, powers and resources. Managed states
now also bind the catalog fingerprint, preventing accidental cross-catalog use.
The familiar 30-card shape is also visible in Blizzard's deck builder:
https://hearthstone.blizzard.com/en-us/deckbuilder/
The selected class/copy/pool restrictions above are this project's pinned policy.

API-01: schemas/integration.schema.json is the one current integration schema,
separate from the executable card-language schema. Draft 2020-12 $defs name
command, action, observation, view, event and checkpoint contracts. API version
2.0 envelopes are closed; commands contain apiVersion, sequence and action.
Actions retain the documented existing dictionaries; target/position may be
null to mean omitted. Python booleans/floats are rejected for integer arguments.
An action schema describes shape; execution validators decide live legality.
Observations contain apiVersion, sequence, a detached view and legalActions.
Events in views use the typed field allowlist in $defs/event; sensitive fields
can be absent due to redaction. These are full projections, not append-only
incremental event streams: visibility may change when a card becomes public.
Raw event logs and private state fields are opaque implementation details.
API-02: Session owns a detached private state. observe(player) is the client
boundary. submit(player, command) accepts a command only at the current sequence,
executes atomically, then increments it once, including a pending-choice pause.
Failed, duplicate or stale submissions leave sequence/state unchanged; refresh
observations after a stale-command error. The host supplies authenticated player
identity separately, serializes submissions and stores private checkpoints. This
is a synchronous integration adapter, with no network, authentication, locking,
or durable database implementation. Clients must never receive checkpoint().
API-03: engine.checkpoint(state, sequence=0), engine.restore(checkpoint),
Session.checkpoint() and Session.resume(engine, checkpoint) persist private JSON.
Checkpoint 2.0 pins rulesVersion foundation-rules-12, catalog fingerprint, all
resolution budgets, session sequence, payload and checksum. Restore rejects
unknown versions, incompatible catalogs/budgets and corrupted payloads. Validate
boundary phases, IDs, definitions/kinds, zones, deck membership, hero identities,
powers/classes, resource consistency/caps, entry chronology, capacities and
mulligan selections. Pending continuations must replay to the exact saved state;
nested pending checkpoints and unfinished runtime frames are rejected. Restored
logs regain immutable payloads. Checksums detect corruption, not authenticity;
private checkpoints are trusted server storage, not hostile client submissions.
Views cannot be restored. Internal state payloads are opaque and supported only
under their exact checkpoint/rules version; legacy raw JSON has no compatibility
promise. Metadata-only catalog changes also invalidate checkpoints deliberately.
API-04: Consumers negotiate exact apiVersion using engine.contract(). Changed
required fields, meanings, event variants or enum values require a new API
version; old versions are rejected unless explicit migration support is added.
Checkpoint layout changes require a checkpoint version change; execution changes
require a rules version change. No implicit migrations or old-version branches.
Catalog identity alone is insufficient: exact fingerprint compatibility applies.
Python ValueError indicates invalid/stale input; its human diagnostic text is not
a stable machine error-code contract. examples/play_client.py demonstrates a
complete constructed game from observations only, command replay and private
server checkpoint resumption during Discover.

Pinned profile (stage 12 groundwork)
------------------------------------
All 60 definitions match the pinned CardDefs extraction for Wild build
11.0.0.24118, commit af94b04fdff91a1900f4adfc873d89c76aa298cd. Manifest stores
