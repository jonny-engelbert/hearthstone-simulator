Current card definition and execution contract
=============================================
Updated 2026-10-21: schema 1.10; catalog foundation-v9.1; 52 definitions.
Profile: historical-foundation-fixtures, not one verified live-client patch.

Data and versioning
-------------------
FND-01: Definitions use exact (cardId, revision) references; instances have unique
IDs and owner/controller/zone state. Display text is never executable logic.
FND-02: One current catalog, schema and hash manifest, updated in place. Git
preserves releases. Old revision labels identify definitions, not rule branches.
FND-03: Reject unknown fields, operations, versions, incompatible kinds and
unresolved references. Validate structure before semantic constraints. Diagnostics
identify the relevant discriminated schema branch and offending field/rule.
FND-04: Minions require Attack/Health, weapons Attack/durability, spells/powers
mana cost only. Keywords, mechanics and ability kinds must agree.

Execution and combat
--------------------
Targeting: REQUIRED prohibits play without a legal selection;
REQUIRED_IF_AVAILABLE requires a selection when available; OPTIONAL permits none.
Selectors and selected-target legality are separate (area damage ignores Stealth
and Elusive). Board/hand/deck caps: 7/10/99. Mana is never negative.
Damage: capture a batch's recipients and Spell Damage once; resolve every hit
before its death checkpoint. Shield, Immune and Armor use the common pipeline.
Spell Damage: sum SPELL_DAMAGE amounts on living, non-pending, non-silenced
friendly minions in PLAY. Ignore sources in other zones, and enemy sources.
Only SPELL-class damage receives this bonus, not hero powers, abilities or fatigue.
Healing: cap at damage taken. Buffs are additive. Auras are flat friendly-minion
modifiers. Health loss uses CAP_CURRENT_ON_MAX_LOSS. Silence removes operative
keywords, buffs, Freeze and abilities. Transform resets the instance definition.
Combat: validate readiness, Attack, attack counts, Freeze, Rush/Charge and Taunt;
normal hits/retaliation capture Attack before applying damage. Weapons equip,
replace, spend durability and run destruction scripts through the same scheduler.
Entry stamps are explicit, unique and monotonic; there is no unstamped fallback.

Draws, zones and death resolution
--------------------------------
Draw explicit deck order. A full-hand draw publicly reveals/burns the card.
Empty decks escalate fatigue, even with a full hand. Summons do not run Battlecries.
Generated instances get fresh IDs. Bounce/shuffle reset board modifiers; Gang Up
creates clean base-definition copies. Death snapshots preserve last-known state.
DEATH_WAVES_FIFO: remove each ordered death batch, then resolve its snapshots
before collecting the next wave. Flat aura refreshes and nested deaths settle
before returning control. Reaction/Deathrattle budgets fail atomically.

Managed matches and reaction timing
----------------------------------
Seeded setup/mulligan, Coin, complete turns, mana growth/refill, temporary mana,
Overload locks, power usage, readiness, expiration and Freeze thawing belong to
MatchEngine. Fixture primitives are not legal public player actions.
Counterspell spends mana/card and still counts a play, but suppresses spell text,
Overload and AFTER_SPELL. The hardening review's proposed Overload reversal is
contradicted by Blizzard's archived answer (see reactions-stage9.txt).
Reactions snapshot eligible sources, run depth first with explicit bounded work,
revalidate sources and complete before the next decision. Attack interruptions
can cancel or redirect; a returned state has no pending reaction frames.

Public APIs and privacy
-----------------------
apply accepts mulligan/play/hero_power/attack/end_turn/concede dictionaries.
legal_actions reuses execution validators; returns canonical concrete actions.
Enumerate all mulligan subsets (at most 16), each legal target and each minion
position. Omitted target means none; minion positions are explicit. Equivalent
optional-null/default spellings accepted by apply are not duplicated in the list.
Finished games return []; inactive/waiting players can only concede.
view returns own hand, public entities, counts, public resources and filtered
events. Deck instances/order are hidden for both; opponent hand/Secrets have no
private handles. Public bounce/reveal/exact generation can identify hand cards;
drawing/shuffling clears that knowledge. No RNG, scheduler, stamps, provenance
pointers, death snapshots, mulligan choices or setup deck lists cross this API.
Full states, raw event logs and checkpoints remain private debug data. Views are
not restorable checkpoints. New private random generation will require an
explicit visibility policy when introduced in stage 10.

State copies and development policy
----------------------------------
Actions return independent mutable game state. Historical event payloads are
immutable and shared safely; each state owns its log sequence. JSON export/
restore stays plain and deterministic. Payload list copies are shallow O(n),
not deep copies of all prior events; a fully persistent log is not implemented.
No new per-stage snapshot/doc/report files: update current files and CHANGELOG.
Historical stage notes retain detailed fixture policies; code/tests are current.
Future: random effects/choices, constructed deck legality, typed public contracts,
and a single pinned client/card profile with client-log conformance evidence.
