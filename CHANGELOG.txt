Hardening pass (2026-10-21, before stage 10)
==========================================
1. Git/history: existing baseline 0f37497 already preserves the entire original
   project. Consolidation commit e3beb5c removes old catalog/schema/manifest and
   validation snapshots, version branches and 14 obsolete tests. One current
   catalog/schema/manifest, bumped in place to foundation-v9.1 / schema 1.10.
   Explicit entry stamps replace unstamped fixtures. Examples use current rules;
   the keyword example takes 81 actions (formerly 79), with exact replay.
   outputs/, caches, .DS_Store and local formatter dependencies are ignored.

2. Counterspell/Overload: disagreed with the proposed reversal. Blizzard's
   archived answer says countering prevents Overload. Kept that behavior and
   strengthened Lightning Bolt's test: mana spent, no damage, no pending Overload
   or OVERLOAD event. Original forum page is inaccessible; its primary statement
   is reproduced under Counterspell at:
   https://www.hearthpwn.com/news/64-hearthstone-puzzle-2-blue-posts-extravaganza
   Provenance/limitations are also recorded in docs/reactions-stage9.txt.

3. Spell Damage: removed the manually supplied spellDamage state array. Compute
   bonuses from living, non-silenced friendly SPELL_DAMAGE minions in PLAY, once
   per spell damage operation/batch. Added Kobold Geomancer CS2_142 (2 mana, 2/2,
   Spell Damage +1), bringing the catalog to 52 definitions. Verified its tags
   against HearthSim/hs-data CardDefs.xml. Tests cover stacking, Fireball,
   Flamestrike, source removal, and unaffected powers/fatigue/Battlecries.

4. Legal actions: execution and enumeration share validators. Return canonical
   apply dictionaries with every legal target/position and every opening mulligan
   subset (at most 16); no simulated effects or hidden-Secret probes. Test all
   listed actions and invalid samples, and complete seeded games with invariants
   after every move. HS_RANDOM_GAMES configures the normal six-game property run.

5. Player views: allowlist public state/events, own hand and public resources;
   hide both deck orders/instances, opponent private hand and Secret identities/
   handles, RNG, setup choices and scheduler/death bookkeeping. Opponent DRAW
   hides identity; REVEAL/BURN and public bounces remain visible. Tests include
   hidden identity/ID permutations, deck reorderings and detached-view mutation.
   Full checkpoints/raw logs remain private. Future private random generation
   needs a visibility policy alongside stage 10's new operations.

6. Code quality: PEP 8 formatting with Black 24.10.0; all formatted ASTs were
   verified unchanged. Before/after formatting: 386 tests passed. Refactored the
   effect interpreter into 18 named operation handlers. Replaced all 46 bare
   assertTrue(validate(...)) sites with expected diagnostics; structural errors
   report the relevant discriminated branch. A weapon-kind test previously
   failed on an unrelated leftover trigger field; it now tests the intended rule.

7. Performance: tools/bench.py measures enumeration + execution, excluding

   deep copies of event history with shallow O(n) reference copies, not a fully

Stage 10: random effects and pausable choices (2026-10-21)
---------------------------------------------------------
Current catalog foundation-v10 / schema 1.11, updated in place: 60 definitions.
Added Arcane Missiles, Mad Bomber, Deadly Shot, Babbling Book, Stonehill Defender,
Ironfur Grizzly, Goldshire Footman and Wrath. New card facts are pinned to the
HearthSim/hs-data revision recorded in docs/sources/stage10-card-facts.json.
Book and Stonehill use verified newer Health (1/2, 1/5); this remains a mixed
fixture profile, not a claim of single-client-patch conformance.

Seeded random recipients, sequential missiles with death/reaction retargeting,
extra Spell Damage hits, and filtered collectible card pools use saved RNG state.
Random/Discovered cards and full-hand generated discards are private; public play
or Secret reveal exposes the appropriate identity without exposing old offers.

Typed CHOICE requests and choose actions use bounded deterministic transaction
replay from a private JSON checkpoint. A pause retains committed board/resources/
RNG/events; the final selection commits the command once. Supports nested choices,
off-turn listeners, Deathrattles and turn-start resume without serializing Python
stacks or exposing half-resolved deaths. Countered effects skip choices/randomness.
Pool scope/weighting, shared-target Choose One and atomic protocol timing are
explicit in docs/requirements.txt; these are not inferred from card text.
